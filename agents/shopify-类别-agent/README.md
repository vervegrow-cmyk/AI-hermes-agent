# shopify-类别-agent

`shopify-类别-agent` 是一个面向 Shopify 已上架商品的分类优化 agent，目标是持续提升商品“类别”和“类别元字段”的准确性、完整性和一致性。

它基于 Shopify 商品编辑页中的类别、类别元字段和可用建议信息，结合商品标题、描述、图片、SKU、供应商信息以及 `DeepSeek` 大模型的语义理解能力，对店铺存量商品进行分类诊断、建议生成和安全写回。

## 一句话定义

这是一个以“尽可能更合理、更完整地优化 Shopify 商品类别和类别元字段”为目标的商品分类治理 agent。

## 项目要解决的问题

当前 Shopify 商品数据里常见的问题包括：

- 商品类别为空
- 商品类别错误或过粗
- 同类商品分类标准不一致
- 类别元字段缺失或填写不规范
- Shopify 已存在建议，但没有被系统化利用

这些问题会影响：

- 店铺前台搜索和筛选
- 商品推荐和集合组织
- Google / Meta / YouTube 等渠道 feed 质量
- 商品数据标准化程度

## 目标主链

这个 agent 预期形成的主链很明确：

1. 读取 Shopify 商品当前类别、类别元字段和相关商品信息
2. 优先利用 Shopify 已存在的类别或字段建议
3. 当 Shopify 没有可直接采用的建议时，使用 `DeepSeek` 生成补充建议
4. 输出建议类别、建议元字段、风险等级和决策说明
5. 在 `dry-run` 或人工确认后，按需写回 Shopify

核心原则是：

- 有 Shopify 建议时优先参考 Shopify
- 无明确 Shopify 建议时由 DeepSeek 补充判断
- 不确定或高风险样本进入人工复核

## 当前能力边界

目前这个 agent 更准确的定位是：

- 已完成基础工程接入
- 已完成 Shopify / DeepSeek 能力验证
- 已完成第一版分类优化主链
- 仍需继续增强 Shopify 建议抓取和批量治理稳定性

因此，它现在已经是一个可运行的专项 agent，但还不是覆盖所有分类场景的最终成熟版本。

## 预期核心能力

后续主链完成后，系统核心能力会集中在四块：

- Shopify 商品类别与类别元字段读取
- Shopify 建议优先、DeepSeek 补充的分类决策
- 类别元字段补全与规范化
- `dry-run` / `apply` 模式下的安全写回与审计

## 与人工运营的关系

这个 agent 的目标不是完全替代人工，而是把高重复、低效率、难统一标准的分类工作自动化。

更合适的协作方式是：

- 系统处理高置信度样本
- 人工复核边界模糊或高风险样本

## 本地启动

在仓库根目录执行：

```powershell
python agents/shopify-类别-agent/main.py
```

或者在当前目录执行：

```powershell
python main.py
```

默认端口为 `8088`，可通过 `AGENT_PORT` 覆盖。

- `GET /health`

## 开发目标

当前阶段，这个 agent 的开发目标可以收敛为以下四项：

### 1. 打通商品分类读取主链

能够稳定读取 Shopify 商品的基础信息，以及与分类相关的核心字段，包括：

- 商品标题、描述、图片、SKU、Vendor、Product Type、Tags
- 当前 `category`
- 当前 `metafields`
- 可用的 Shopify 建议信息

### 2. 建立分类决策主链

形成明确可执行的分类判断流程：

- 有 Shopify 建议时优先参考 Shopify 建议
- 无明确 Shopify 建议时调用 `DeepSeek` 生成补充建议
- 对不确定、高风险或冲突样本进入人工复核

### 3. 建立类别元字段补全能力

在类别确定后，能够围绕目标类别输出相应的类别元字段建议，并尽量保证：

- 字段完整
- 字段值合理
- 表达统一
- 可用于后续平台搜索、筛选和渠道分发

### 4. 建立可控写回能力

支持分类优化结果的安全落地：

- `dry-run` 模式下只输出建议和审计结果
- `apply` 模式下按规则写回 Shopify
- 所有写回行为保留审计记录

## 完成标准

这个 agent 不以“代码写了多少”为完成标准，而以“主链是否真正可跑、结果是否可控”为完成标准。

### 第一层：连通完成

满足以下条件，视为基础连通完成：

- 可以稳定连接 Shopify 店铺
- 可以稳定读取商品 `category`
- 可以稳定读取商品 `metafields`
- 可以成功调用 `DeepSeek`

### 第二层：主链完成

满足以下条件，视为分类主链完成：

- 能够读取目标商品的分类相关输入数据
- 能够输出建议类别
- 能够输出建议类别元字段
- 能够区分 Shopify 建议优先和 DeepSeek 补充判断两种路径
- 能够标记高风险样本进入人工复核

### 第三层：执行完成

满足以下条件，视为执行链完成：

- 支持 `dry-run` 输出结构化建议结果
- 支持 `apply` 模式写回 Shopify
- 写回结果可校验
- 写回前后有记录可追踪

### 第四层：可用完成

满足以下条件，视为该 agent 达到可用阶段：

- 可以针对一批真实已上架商品运行
- 输出结果具备可读的决策说明
- 高置信度样本可直接应用
- 低置信度样本可进入人工复核
- 整体流程不会因单个商品异常而中断

## 建议验收口径

为了避免“看起来做完了，但实际上还不能用”，建议按以下口径验收：

1. 随机抽取一批真实 Shopify 商品运行 `dry-run`
2. 检查是否成功输出类别建议和类别元字段建议
3. 检查是否区分 Shopify 建议路径与 DeepSeek 路径
4. 检查高风险样本是否被正确拦截
5. 选取小批量商品执行 `apply`
6. 检查 Shopify 后台写回结果是否符合预期

如果以上链路可以稳定跑通，就可以认为这个 agent 已经完成当前阶段的核心开发目标。
