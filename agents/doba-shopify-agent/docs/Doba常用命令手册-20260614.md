# Doba 常用命令手册 20260614

## 手册用途

这份手册用于沉淀 `agents/doba-shopify-agent` 的高频实战命令。

当前版本重点收录的命令是：

- 面向 `vendor = Doba` 全量商品的 DeepSeek 优化补齐并真实发布命令

这条命令适用于你当前的核心业务目标：

- 根据商品标题、标签、详情页介绍，调用 DeepSeek 对商品做补齐判断
- 优化补齐 Shopify 主类别 `category`
- 优化补齐产品类型 `productType`
- 优化补齐 Hermes 类别相关元字段
- 真实发布到指定销售渠道
- 将处理过的商品加入 `NEW ARRIVALS`
- 输出实时明细日志和结构化报告

## 核心命令

在 `agents/doba-shopify-agent` 目录下执行：

```powershell
cd "D:\桌面文件下载\AI-hermes-agent\agents\doba-shopify-agent"
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
$env:PYTHONPATH="D:\桌面文件下载\AI-hermes-agent"
Remove-Item Env:HTTP_PROXY -ErrorAction SilentlyContinue
Remove-Item Env:HTTPS_PROXY -ErrorAction SilentlyContinue
Remove-Item Env:ALL_PROXY -ErrorAction SilentlyContinue
Remove-Item Env:http_proxy -ErrorAction SilentlyContinue
Remove-Item Env:https_proxy -ErrorAction SilentlyContinue
Remove-Item Env:all_proxy -ErrorAction SilentlyContinue
$env:PYTHONDONTWRITEBYTECODE="1"

.\.venv\Scripts\python.exe -m src.app.runners.run_publish_vendor_catalog `
  --vendor Doba `
  --channels "Online Store" "Shop" "Pinterest" "Facebook & Instagram" `
  --report-path "docs/audits/doba-force-publish-report-round26-20260614.json" `
  --stop-on-failure 2>&1 | Tee-Object -FilePath "docs/audits/doba-force-publish-round26-live-20260614.log"
```

## 命令能力说明

这条命令会对所有 `vendor` 字段等于 `Doba` 的 Shopify 商品做一次真实执行，不是演练，不是 dry run。

它具备以下能力：

- 按 `vendor:Doba` 抓取全量商品
- 对商品逐个处理，而不是盲目批量写入
- 对每个商品调用一次 DeepSeek
- DeepSeek 会结合商品标题、标签、详情页介绍生成补齐建议
- 尝试补齐 Shopify 原生主类别 `category`
- 尝试补齐 `productType`
- 尝试补齐 Hermes 类别元字段、LLM 元字段、属性建议元字段
- 尝试把商品真实发布到以下渠道：
- `Online Store`
- `Shop`
- `Pinterest`
- `Facebook & Instagram`
- 将每个已处理商品加入 `NEW ARRIVALS`
- 输出实时进度日志
- 输出结构化 JSON 报告
- 一旦出现硬失败，因 `--stop-on-failure` 会立即暂停，避免错误继续扩散

## 这条命令会真实修改什么

执行后，系统可能真实修改以下内容：

- Shopify 商品主类别 `category`
- 商品类型 `productType`
- 商品标签 `tags`
- Hermes 命名空间下的分类相关元字段
- LLM 状态、原因、置信度、原始建议负载
- 商品所在销售渠道发布状态
- 商品集合归属，包含 `NEW ARRIVALS`

## 命令参数中文说明

- `--vendor Doba`
  仅处理 `vendor` 字段等于 `Doba` 的商品。

- `--channels "Online Store" "Shop" "Pinterest" "Facebook & Instagram"`
  强制把目标商品发布到这 4 个渠道。

- `--report-path "docs/audits/doba-force-publish-report-round26-20260614.json"`
  将本次执行的完整结果保存成 JSON 报告，便于后续审计、筛选、复盘。

- `--stop-on-failure`
  遇到硬错误立即中止，方便第一时间定位失败原因。

- `2>&1 | Tee-Object -FilePath "...live-20260614.log"`
  让控制台实时输出同时写入日志文件，便于边跑边看，也便于事后分析。

## 实时明细输出说明

执行时通常会看到以下几类日志：

- `loading publications for vendor=Doba`
  表示正在加载目标销售渠道。

- `deepseek_status=enabled:model=deepseek-chat`
  表示 DeepSeek 已启用。

- `fetching product page N for query=vendor:Doba`
  表示正在分页抓取所有 Doba 商品。

- `X/821 optimizing gid://shopify/Product/...`
  表示正在处理第 X 个商品。

- `detail category=旧类别 -> 新类别`
  表示 Shopify 主类别的变化。

- `detail llm=parsed pt=... label=... conf=...`
  表示 DeepSeek 已成功解析，并给出产品类型、类别标签、置信度。

- `detail collection=yes | published=... | missing=-`
  表示商品已加入集合，并已覆盖全部要求渠道。

- `done action=category_applied collection=yes publish_error=no source_error=no`
  表示这个商品本轮已成功完成主要处理。

## 常见结果状态说明

- `category_applied`
  已成功写入 Shopify 主类别。

- `category_suggested_review`
  系统识别到了方向，但当前 taxonomy 映射不够安全，降级为建议复核。

- `llm_suggested_review`
  DeepSeek 已给出建议，但当前还不能安全直写主类别。

- `no_match`
  现有规则与模型结果都没有形成可落库的稳定写入方案。

- `publish_error=yes`
  渠道发布环节出现错误。

- `source_error=yes`
  产品类型、标签或 Hermes 元字段写入环节出现错误。

## 使用建议

适合使用这条命令的场景：

- 全量 Doba 商品重新优化补齐
- 需要 DeepSeek 全量参与分类补齐
- 需要真实发布到 4 个目标渠道
- 需要实时明细输出
- 需要把商品加入 `NEW ARRIVALS`
- 需要出现硬失败就立刻暂停

不适合使用这条命令的场景：

- 只想做 dry run
- 只想验证少量样本
- 只想做 taxonomy 规则开发，不希望触碰 Shopify 真实数据
